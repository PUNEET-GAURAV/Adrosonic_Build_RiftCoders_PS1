# ADR-004: Client-side fusion (RRF / weighted / DBSF)

Status: Accepted

## Context
Dense and BM25 scores live on incompatible scales. Need a fusion step, documented and
configurable (FR-3). The PRD preferred server-side RRF in the Qdrant Query API.

## Decision
Fuse **client-side** in `core/fusion.py`: two store calls (dense + sparse, each carrying the
same filter), then RRF (default), weighted-linear (min-max normalised) or DBSF in Python.

## Consequences
- Portable across `qdrant-client` versions (no dependency on a specific Query-API fusion
  signature), deterministic, unit-testable offline, and gives per-leg rank/score for
  explain mode for free.
- Cost: two round-trips instead of one (~1–2 ms on localhost), well inside the 150 ms budget.
  The store port could later add a server-side fusion path without changing the core.
