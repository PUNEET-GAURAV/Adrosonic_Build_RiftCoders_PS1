# ADR-002: BM25 as sparse vectors with a self-contained encoder

Status: Accepted

## Context
Hybrid search needs a BM25 leg. Options: an external in-memory index (`rank_bm25`/`bm25s`)
or BM25-as-sparse-vectors inside Qdrant.

## Decision
Store raw term frequencies as sparse indices (stable 32-bit FNV-1a token hashes) with
`Modifier.IDF`, so Qdrant computes IDF server-side over the live corpus. We use a
**self-contained tokeniser** (`core/text.py`) rather than `fastembed`, avoiding the
`onnxruntime`/`tokenizers` dependency.

## Consequences
- Live upserts/deletes keep BM25 statistics current; filters apply to the sparse leg; one
  round trip per leg.
- Hashed indices are a pragmatic vocabulary-free choice (collisions negligible at 32-bit).
  A source-system vocabulary could replace it later without changing the port.
