# ADR-001: Qdrant as the single store

Status: Accepted

## Context
Need one store that holds dense vectors, BM25 sparse vectors and payload on the same point,
so filters, updates and deletes apply consistently to every retrieval leg.

## Decision
Use **Qdrant** (Docker, local). A named dense vector (384-d, cosine) and a sparse vector
(`bm25`, `Modifier.IDF`) plus payload live on one point. Alternatives considered: pgvector
(sparse support weaker), ChromaDB (no native sparse fusion at the time), Weaviate (heavier).

## Consequences
- Native dense + sparse on one point; payload indexes; upsert/delete by deterministic ID;
  quantization and snapshots for reproducibility.
- Requires Docker. Mitigation: an `InMemoryStore` adapter powers the small demo and tests.
